PTLT 首次完整技术审计。执行时项目已停滞约三个月（最后一次代码改动 2026-05-03），并在同一天
首次纳入版本控制。

**方法**：10 个并行只读 agent，覆盖后端架构、前端、构建与部署就绪度，以及对抗式缺陷/安全审查。
本仓库共确认 **20 个缺陷**，每条都对照源码验证过并给出文件位置。

## 2. 三个结构性发现

这三条比任何单个 CVE 都更能说明项目状态。

1. **核心功能没有录入入口。** 稳定度分数、当前/最长 streak、Dashboard 图表、整个 Analytics 页
   全部读 `DailyRecord`。`DailyRecordController` 的 4 个端点存在且可用，**但没有任何 React 页面
   调用它们**。这是一个为不存在的数据做的仪表盘。补上这一个录入页，一次性解锁四块已经写好的功能。

2. **后端 serve 的是错的前端。** `pom.xml` 没有 `frontend-maven-plugin`，`frontend/` 里的 React
   应用从不打进 jar；而 `SecurityConfig` 放行了 `/`、`/index.html`、`/*.js`、`/*.css`，
   所以直接跑后端 serve 的是 `src/main/resources/static/` 里更早的 vanilla JS 版本。
   两个 UI 并存，赢的是被废弃的那个。

3. **项目在 JDK 24+ 上根本编译不了，且报错被吞掉。** Lombok 1.18.36 不支持 JDK 24 以上，
   而 `maven-compiler-plugin` 配了 `<fork>true</fork>`，forked javac 的诊断信息全部丢失 ——
   构建日志里只剩一句没有信息量的 "Compilation failure"。已升级到 1.18.42，JDK 21 与 25 均验证通过。
   这解释了为什么项目看上去"坏了"却查不出原因。

## 3. 当天已修复

| # | 严重度 | 问题 | 提交 |
|---|---|---|---|
| 1 | critical | `application.yml` 提交了可用的 JWT 默认密钥且**无任何启动守卫**。每个 Controller 的 `userId` 和 `workspaceId` 都只从 token 派生，所以这一个密钥是全部认证和全部租户隔离的根 —— 伪造 token 可以绕过第 1 节里那层写得正确的隔离 | `dbdbfdc` |
| 2 | critical | `validateToken` 只验签名与过期，从不检查 `generateRefreshToken` 打上的 `type` claim，而 `generateAccessToken` 根本不打 type。**refresh token 因此可以当 access token 用**：登出形同虚设，被捕获的 token 在其 7 天有效期内仍能调用任何只需 userId 的端点，包括 `DELETE /api/v1/workspaces/{id}` | `dbdbfdc` |
| 3 | high | workspace 软删除只置 `workspaces.deleted_at`，成员行不动；`findFirstByOwnerId` 也不过滤 `deleted_at`，登录时照样选中已删除的 workspace。用户退出再登录，全部数据端点照常工作 —— 删除纯属装饰 | `8d0add8` |
| 4 | high | `invite` 只拦 VIEWER，之后原样采用请求里的 role：EDITOR 可以邀请一个自己控制的账号为 OWNER，用它登录即满足 delete 的 OWNER 校验 —— **两个 HTTP 调用从 EDITOR 提权到删库** | `8d0add8` |
| 5 | high | CORS `allowedOriginPatterns("*")` + `allowCredentials(true)`，对任意站点关闭浏览器同源隔离 | `6ee7c8d` |
| 6 | high | `SyncService.push` 校验成员身份后**完全忽略请求体**，返回 `pull()` 的结果包在 `ApiResponse.success()` 里。离线客户端收到 200 和新游标会清空发件箱 —— **伪装成成功的数据丢失** | `fe77652` |

**旧的 JWT 签名密钥视为已泄露。** 此前签发的 access token 全部失效（它们没有 `type` claim）。

### 前端 lint 债

CI 首次运行 ESLint 时报出 21 个错误。可机械修复的 16 个已改（未使用的 import、未使用的参数）。
剩余 5 个需要真正重构，CI 的 lint 步骤因此暂设为 `continue-on-error`：

- `react-hooks/set-state-in-effect` ×4（Dashboard / Routines / Tasks）—— 页面用
  `useEffect(() => { fetchX(); }, [fetchX])` 取数，要消除需改成 router loader 或 react-query
- `react-refresh/only-export-components` ×1（`hooks/useAuth.jsx`）—— 该文件同时导出
  `AuthProvider` 组件和 `useAuth` hook，需拆成两个文件

**eslint 配置没有被放宽** —— 修的是源码，不是规则。

## 5. 市场判断

个人时间/习惯追踪是一个**增长但极度拥挤、且几乎不付费**的品类：市场规模约 $2.22B（2026）
→ $6.41B（2034），CAGR 14.2%，但绝大多数应用免费，Toggl、RescueTime、Sunsama、Amazing Marvin、
Notion 模板挤满，独立开发者的触达能力接近零。

**结论：PTLT 作为自用工具值得完成，作为生意不值得。** 详见
[`adr/0001-personal-tool-not-a-product.md`](../adr/0001-personal-tool-not-a-product.md)。

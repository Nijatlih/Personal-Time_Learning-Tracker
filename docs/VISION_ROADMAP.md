# PTLT 远景路线图

- **状态**：方向记录，尚未承诺实施
- **记录日期**：2026-08-20
- **原则**：先真实使用，再按实际阻力逐步落地；不机械合并三个项目

## 一句话愿景

> Daily Schedule 负责“今天怎么执行”，AI Plan 负责“长期往哪里走”，PTLT 负责把两者连接起来。

PTLT 继续定位为单用户、单 workspace 的自用工具，不转向商业产品。未来增强的目标不是增加功能数量，
而是形成一条清晰的个人闭环：

1. 长期学习目标与阶段里程碑
2. 本周与今天的计划
3. 实际执行、偏差与原因
4. Daily Log、稳定度与复盘

## 可借鉴的两个独立项目

### `Nijatlih/daily-schedule-tracker`

最有价值的是“当天执行层”：

- 时间段任务与周视图
- 计划时长和实际时长
- 完成、未完成、跳过、顺延
- 未完成原因与诊断
- 核心、重要、弹性三级优先级
- 固定模板与“今日降载”
- 周复盘、类型投入和连续性统计

它的优势是帮助用户在当天做决定，而不仅是事后展示统计。

### `Nijatlih/ai-weiterbildungsplan-2026`

最有价值的是“长期学习层”：

- 阶段 → 月/周 → 学习任务的层级
- 未开始、进行中、已完成三态
- 预计时间、交付物、验收标准
- 证据/GitHub 链接与备注
- 搜索、筛选、折叠和进度概览
- 起止日期、倒计时、最近待办和逾期提醒
- 有版本与来源校验的 JSON 备份导入

核心理念：完成不应只是打勾，重要学习成果应有证据或可验证交付物。

## 推荐实施顺序

### Phase A — Schedule（日程执行层）

**优先级最高。** PTLT 后端已有 `TimeBlock` 和 `ScheduleSlot`，先补前端，不急着改 schema：

- 今日时间轴
- 周视图
- 创建、编辑时间块
- 固定每周日程模板
- 时间块关联 Task
- 计划时间汇总

这是现有后端能力到真实日常价值之间最短的一步。

### Phase B — 增强任务执行记录

只有在真实使用证明需要后再做，预计涉及数据库迁移：

- `CORE / IMPORTANT / FLEXIBLE`
- 完成、未完成、跳过、顺延
- 实际投入分钟
- 未完成原因和执行备注
- “今日降载”：保留核心/重要，跳过弹性任务
- 计划时间与实际时间对比

设计前必须先明确 Task 定义、某日 TaskInstance 和 TimeBlock 三者的职责，避免重复存储同一个状态。

### Phase C — 轻量级 Learning Plan

建立长期方向到每日执行的连接：

- 学习计划、阶段和里程碑
- 学习项状态、预计时间、截止日期
- 证据链接、备注、交付物和验收标准
- 搜索、筛选和阶段进度
- 从 JSON 导入个人计划

不把另一个仓库的 498 个任务硬编码进 PTLT。PTLT 保存阶段与核心里程碑；每天的具体学习活动进入
Schedule/Tasks。现有 `BootcampModule` 的 M1–M7 模型过于简单，实施前应先决定是演进它还是设计新的
workspace 级学习计划模型，不能直接把层级数据硬塞进去。

### Phase D — 统一 Dashboard

首页最终只需清楚回答四个问题：

1. 今天最重要的事情是什么？
2. 今天安排了哪些时间块？
3. 当前学习阶段进度是多少？
4. 最近有什么截止日期或逾期事项？

Dashboard 只展示真实数据，不生成未经数据支持的建议或百分比。

## 暂不纳入

- **完整求职/Offer 管理**：生命周期临时、数据敏感且领域独立，继续保留在私有的
  `ai-weiterbildungsplan-2026` 中。未来最多把“下一步日期”作为通用截止事项接入 PTLT。
- **番茄钟**：容易实现，但当前不是核心价值。
- **复杂 Excel 导出**：先做简单、可恢复的 JSON 和可阅读的 CSV。
- **一次导入 440 个每日任务**：会让日常界面立即过载。
- **复制两个项目的前端代码或 localStorage 数据模型**：只吸收产品理念和已验证工作流，按 PTLT 的
  React + Spring Boot + PostgreSQL 架构重新实现。

## 决策门槛

在添加任何阶段前，至少回答：

- 真实使用中哪一步反复造成阻力？
- 新功能是否会每周至少使用一次？
- 现有 Task、TimeBlock、ScheduleSlot 或 Bootcamp 模型能否正确承载？
- 是否能先做更小的 UI/查询改动，而不是立即增加表和端点？
- 新数据是否有明确的录入入口、展示位置和删除/修正方式？

## 下一次评估

先连续真实使用当前 PTLT 至少一天，记录：

- 哪个操作不自然或重复
- 哪些统计没有帮助
- 哪类信息每天仍需去别处查看
- Schedule、Learning Plan、任务执行增强中，哪一个最能减少实际摩擦

根据使用反馈决定是否启动 Phase A；本文件本身不代表这些阶段已经进入开发计划。

## PTLT 这个代号是哪来的

`ptlt_settings` / `ptlt_records` / `ptlt_tasks` 这个 localStorage 键命名空间第一次出现在
`developer-documentation.md` 的「数据存储结构设计」一节（源自 v1.1/v2.docx）。
三天后，`com.nijat.ptlt` 成了这个仓库的 Java 包名——代号先于代码存在。

## 和现在的代码是什么关系

**这份文档描述的设计从未被完整实现过。** 三条线各走各的：

- 这里的文档假设：浏览器离线单页应用，React + Zustand + `localStorage`，14 个业务字段、
  番茄钟、能量预算、目标树等一整套个人系统
- 这个仓库实际实现的：Spring Boot + PostgreSQL + React，workspace 级多租户，
  14 张表 47 个端点——技术栈、数据模型、多租户前提都和这份文档不一样
- 另外还有一个更早的独立原型（vanilla JS + Chart.js 单页应用），用的是完全不同的
  `scheduleData` 存储 key，也没有照这份文档做，只存在于本地，没有进过任何仓库

也就是说：**这份文档是需求分析阶段的产物，不是这个仓库的实现说明书。** 参考价值在于
它记录了最初想解决什么问题、设计过哪些功能——其中不少（能量预算、目标树、反人性规则、
稳定度打分）从未进入这个仓库的 SDD 或任何一版实现。想找"当初为什么要做这个"的答案，
看这里；想找"现在系统怎么运作"，看仓库根目录的 `README.md` / `CLAUDE.md` / `SDD.md`。

## 已知的设计分歧（供参考，不代表现状）

这份文档自身的 v1.0/v1.1 之间也有没解决的矛盾（合并版正文里逐条标注了），比较值得注意的：

- 状态判定算法：v1.0 是一票否决制（五个条件同时满足才算 Green），v1.1 改成加权评分制
  （0–100 分，≥80 Green）——合并版采用 v1.1 版本，v1.0 版本存档在文档内的折叠块里
- 存储方案：v1.0 提的 `window.storage` 是个不存在的 API，v1.1 改成了 `localStorage`
- `Task` 接口：v1.0 版本缺 `quadrant`、`energyRequired` 字段，且优先级类型和正文自相矛盾；
  v1.1 补全了
